## 二、题目要求拆解

1. **数据结构**：`Available`（可用向量）、`Max`（最大需求矩阵）、`Allocation`（已分配矩阵）、`Need`（需求矩阵）；进程数 n、资源种类数 m 由运行时输入。
2. **安全性算法**：判断当前状态是否安全；安全则输出一条安全序列。
3. **请求处理**：请求合理性检查 → 资源是否足够 → 试探分配 → 安全性检查 → 确认或回滚；四类结果都要有输出。
4. **测试场景**：至少两组——安全状态下可满足的请求；会导致不安全状态的请求。可扩展多进程并发请求。

## 三、数据结构设计（草案）

```c
int n, m;                 // 进程数、资源种类数，运行时输入
int Available[M];         // 各类资源当前可用量
int Max[N][M];            // 每个进程对每类资源的最大需求
int Allocation[N][M];     // 当前已分配
int Need[N][M];           // 还需多少 = Max - Allocation
int Request[M];           // 某进程本次请求向量
```

派生量：`Work[m]`（安全性算法的工作向量）、`Finish[n]`、安全序列 `safeSeq[n]`。

## 四、算法骨架（伪代码，待你实现）

### 安全性算法

```
Work = Available;  Finish[所有进程] = false;
while (能找到一个 i 满足 !Finish[i] 且 Need[i] <= Work) {
    假设它执行完，释放资源：Work += Allocation[i];
    Finish[i] = true;  记录进安全序列;
}
若所有 Finish[i] 为 true → 安全；否则不安全（未完成的进程可能死锁）
```

### 请求处理（进程 i 请求 Request）

```
1. Request > Need[i]            → 请求不合理（超过最大需求）
2. Request > Available          → 资源不足，进程等待
3. 试探分配：
   Available -= Request; Allocation[i] += Request; Need[i] -= Request;
4. 调用安全性算法：
   安全 → 确认分配，输出安全序列
   不安全 → 回滚三项修改，输出"系统将进入不安全状态"，进程等待
```
