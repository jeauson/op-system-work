## 四、关键概念（已讲解，证据待补）

| 概念 | 状态 | 说明 |
|---|---|---|
| 内核、用户态、系统调用 | 已讲解 | 用户态程序经系统调用请求内核代办 |
| 内核镜像 `vmlinuz` | 已讲解 | 编译后的机器码，由 GRUB 加载执行 |
| 源码 / 编译产物 / 运行内核 | 已讲解 | 源码可反复改；产物可重编；运行中的内核改不了，必须重启 |
| 系统调用表 | 已讲解 | 内核镜像的一部分，新增调用必须重编；表由 `syscall_64.tbl` 生成 |
| 调用路径 | 已确认（答题） | 用户态把号放 `rax`、参数放 `rdi` 等；内核用号作下标查 `sys_call_table` 取函数 |
| LKM 与编译内核的区别 | 已讲解 | LKM 是"夹活页"，新增系统调用是"改目录" |
| `.config` 与 `localmodconfig` | 已讲解 | `.config` 三态 y/m/n；`localmodconfig` 按 `lsmod` 关掉当前未加载的模块，是启发式推断 |
| 系统调用返回值约定 | 已讲解 | 内核用 -1~-4095 表示错误；glibc 的 `syscall()` 会把它转成 errno 并返回 -1，负数结果会被误判，需从 errno 还原 |
| `SYSCALL_DEFINE1` 宏 | 已讲解 | 展开为 `long sys_cube(int n)`；名字必须与 tbl 第四列一致 |
| `SYSCALL_DEFINE2` 与指针出参 | 已讲解 | 返回值为 0/负 errno，结果写进用户指针，负数结果不再与错误码冲突 |
| `__user` 标注 | 已讲解 | 给 sparse 检查器看的，gcc 忽略；表示该指针指向用户空间，不能直接解引用 |
| `copy_to_user` | 已讲解 | `copy_to_user(to, from, n)`，返回未拷贝成功的字节数，0 为成功；内部做 `access_ok` 与异常处理 |
| `-EINVAL` / `-EFAULT` | 已讲解 | 前者参数无效（越界、空指针），后者地址不可访问；内核必须返回 `-errno`，裸 `-1` 会被当作 `-EPERM` |
